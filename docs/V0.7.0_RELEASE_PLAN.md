# v0.7.0 Release Plan: In-App Updates

Status: candidate only. This release cannot ship until the signing and
notarization gates below are complete. A docs-only update to this plan does
not bump `VERSION`, change the app, or create a release.

## Product outcome

Token Bar can discover the latest stable release from the public GitHub
Releases channel and show the installed version, available version, release
notes, verification state, and an `Update` action in Settings. An opt-in
automatic check discovers updates; the user still confirms download and
installation. The running app remains usable until verification succeeds.

## Required gates before implementation

- [ ] A Developer ID Application identity is available on the release Mac.
- [ ] The release path signs, notarizes, staples, and verifies the final app
      bundle before publishing it.
- [ ] An updater signing key is generated outside the repository and its
      private half is kept off GitHub. Only the public verification key is
      embedded in the app.
- [ ] Sparkle 2, or another maintained signed updater, is selected after a
      review of its current security and macOS 14 support.
- [ ] The public release feed and versioned artifacts are served only over
      HTTPS. Drafts, pre-releases, arbitrary mirrors, and user-configured
      update URLs are rejected.

## Implementation work package

The feature worker must use a separate branch and worktree and keep the
write scope narrow:

1. Add the maintained updater dependency and a thin app controller. Keep
   release metadata and updater state out of `TokenBarCore` usage semantics.
2. Add Settings controls for `Check for Updates`, opt-in automatic checks,
   current/latest versions, release notes, verification state, progress,
   cancel, retry, and sanitized errors.
3. Configure the fixed public release feed and stable macOS artifact channel.
   Ignore drafts, pre-releases, incompatible systems, and same-or-older
   versions.
4. Preserve sync configuration, pricing cache, chart preference, and login
   item state across replacement. Use the maintained updater's atomic
   replacement and rollback behavior; do not write a custom shell installer.
5. Add synthetic fixtures and tests for feed parsing, SemVer comparison,
   current/no-update, update available, draft/pre-release filtering,
   cancellation, retry, verification failure, rollback, and privacy.
6. Extend the release workflow to produce signed/notarized updater metadata
   and artifacts only from the protected release environment. CI must never
   receive signing or updater private keys.

## Verification and release gates

- Independent review checks the final diff and the exact SHA tested by CI.
- macOS `swift build` and `swift test` pass on the supported toolchain.
- Linux mirror logic, shell syntax, privacy, release, site, versioning, and
  popover contract checks pass.
- The full Mac visual matrix covers Settings in light/dark, empty/current/
  available/error/cancel states, Reduce Transparency, Increase Contrast,
  keyboard focus, VoiceOver labels, and clipping.
- A release-candidate install verifies bundle version, signature, notarization,
  updater feed, one running process, preserved settings, and rollback.
- The feature PR merges first. A separate release PR then bumps `VERSION` and
  `CHANGELOG.md`, followed by the exact `v<VERSION>` tag and published-asset
  verification.

Until every required gate passes, releases remain download-only and the app
does not download or install updates from GitHub.
